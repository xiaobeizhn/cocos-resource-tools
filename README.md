# Cocos Resource Tools

一款 Cocos Creator 编辑器扩展，把两件相关的事放在一个包里：

- **Prefab 依赖清理** —— 找出没有被指定 Prefab 依赖的资源，批量删除并同步清理 `.meta`。回答「**谁没被用**」。
- **资源 Prefab 引用查询** —— 找出一个资源被哪些 Prefab 的哪些节点属性引用，并能直接定位到节点。回答「**被谁用了**」。

两者共用一套子资源 uuid 规则，并且在清理列表里可以对任意一项直接查引用——删之前先确认真的没人用。

> 本扩展由原先独立的 `resource-cleaner` 与 `resource-usage` 合并而来，包名统一为 `resource-tools`。

## 功能特性

### 依赖清理（面板：Prefab 依赖清理）

- 🖱️ **右键入口**：在资源管理器中右键目标 Prefab（或存放 Prefab 的文件夹），选择「Prefab 依赖清理」直接带路径打开面板
- 🔎 **依赖扫描**：通过 BFS 递归收集指定 Prefab（支持文件夹或单个 `.prefab` 文件）的直接与间接依赖，精准定位未引用资源
- 📄 **脚本自动排除**：`.ts/.js` 等脚本属于逻辑代码，不参与资源清理，扫描摘要里会显示被忽略的脚本数
- 📂 **路径自动补全 + 文件夹选择**：输入框支持项目内路径自动补全，依赖资源文件夹右侧的 📂 按钮可调起系统文件夹选择框
- ✅ **批量选择删除**：支持全选 / 手动勾选 / 单击行切换选中，一键批量删除未使用资源
- 🖱️ **双击定位**：双击列表项可在 Cocos 资源管理器中定位并选中对应资源
- 👁 **预览按钮**：每项右侧预览按钮，单击在资源预览界面中显示该资源
- 🔍 **引用按钮**：每项右侧的「引用」按钮，直接对该资源执行引用查询并打开引用面板
- 🗑️ **同步清理 .meta**：删除资源时自动同步清理对应的 `.meta` 文件，避免残留
- 🛡️ **安全确认**：删除操作前弹出确认对话框，防止误删

### 引用查询（面板：资源 Prefab 引用）

- 🖱️ **右键入口**：在资源管理器中右键任意资源文件，选择「查找 Prefab 引用节点」
- 🧭 **节点级定位**：列出引用该资源的 Prefab、节点路径与组件属性路径（如 `cc.Sprite.spriteFrame`）
- 🎯 **点击定位节点**：点击节点路径会打开对应 Prefab 并在层级管理器中选中该节点；节点已被改名或删除时给出提示而不是静默失败
- 🖼️ **子资源识别**：选中一张 `.png` 时，Prefab 里对它的 SpriteFrame 子资源的引用同样会被找到

## 环境要求

- Cocos Creator **≥ 3.8.8**

## 安装

1. 将 `resource-tools` 文件夹复制到项目的 `extensions/` 目录下（**目录名必须与包名一致**）：

```
your-project/
└── extensions/
    └── resource-tools/
        ├── package.json
        ├── main.js
        ├── assets-menu.js
        ├── panels/
        │   ├── cleaner.js
        │   └── usage.js
        └── lib/
```

2. 若此前装过独立的 `resource-cleaner` 或 `resource-usage`，请先从 `extensions/` 中删除，避免重复的右键菜单项。
3. 在 Cocos Creator 中重新加载编辑器，扩展会自动加载。

## 使用方法

### 清理未使用资源

1. 在 **资源管理器** 中右键要清理的目标 `.prefab` 资源（或存放 Prefab 的文件夹），选择 **Prefab 依赖清理**，面板会打开并自动填入该资源路径
2. 在面板中确认 / 填写：
   - **Prefab 路径**：右键进入时已自动填好；也可手动改为目录路径（如 `db://assets/prefabs`）或单个 `.prefab` 文件路径（如 `db://assets/prefabs/ui.prefab`），后者只分析该 Prefab 的依赖
   - **依赖资源文件夹**：需要清理的资源目录路径（如 `db://assets/textures`）。可直接输入（带自动补全），也可点击路径栏最右侧的 **📂** 按钮，在系统文件夹选择框中挑选目录（会自动换算成 `db://` 路径；所选目录必须在项目的 `assets` 下）
3. 点击 **开始扫描**，等待扫描完成
4. 对拿不准的项点击 **🔍 引用**，确认它确实没有被任何 Prefab 引用
5. 勾选需要删除的未使用资源（支持全选）
6. 点击 **删除选中资源**，确认后执行删除

### 查询资源引用

1. 在 **资源管理器** 中右键任意资源，选择 **查找 Prefab 引用节点**
2. 引用面板列出每个命中的 Prefab、节点路径与组件属性
3. 点击 **打开预制体** 进入该 Prefab；点击 **节点路径** 直接在层级管理器中选中对应节点

## 工作原理

**依赖清理**

1. 读取作为依赖根的 Prefab：若输入的是 `.prefab` 文件则只取该单个文件，若是文件夹则递归收集其下所有 `.prefab`
2. 通过 `asset-db` 的 `query-asset-dependencies` 接口，BFS 递归收集所有 Prefab 的直接和间接依赖（Prefab → 材质 → 贴图等）
3. 将依赖 uuid 规范化为文件级基础 uuid（去除子资源后缀 `@xxx`），确保匹配准确
4. 对比依赖资源文件夹中的所有资源（排除目录、`.meta` 与脚本），找出未被任何 Prefab 引用的资源
5. 删除时通过 `delete-asset` 接口删除资源，并兜底清理残留的 `.meta` 文件

**引用查询**

1. 列出 `db://assets` 下全部 `.prefab`，逐个读取并解析其 JSON
2. 在扁平的 `__id__` 数组上重建「节点 → 名字路径」映射
3. 深度遍历每个组件的属性树，匹配 `__uuid__`（文件级目标会连同它的子资源一起命中）
4. 定位节点时按**名字路径**在实时节点树里做广度优先后缀匹配——Prefab 文件里的 `_id` 恒为空串，编辑器分配的运行时 uuid 每次重载都会变，只有名字路径是稳定的

## 注意事项

- ⚠️ 删除操作不可撤销，请仔细确认后再执行
- ⚠️ **清理判定的边界**：「未使用」只相对于你传入的那批 Prefab。场景（`.scene`）里的引用、代码里 `resources.load('path/to/asset')` 这类按字符串路径的动态加载，都**不算**引用，会被报成未使用。引用查询同样只扫描 `.prefab`。删除前请结合项目实际情况判断
- 引用查询每次都会重新读取并解析全部 Prefab，没有缓存；Prefab 数量多的项目单次查询会占用主进程数秒
- 扩展首次加载时 `asset-db` 可能未就绪，内部会自动重试等待
- 子资源（如 SpriteFrame）会被自动归并到文件级进行判断，不会误删

## 开发

纯 CommonJS，零运行时依赖，无构建步骤。核心逻辑抽在 `lib/` 下的纯函数中，可脱离编辑器测试：

```bash
npm test
```
